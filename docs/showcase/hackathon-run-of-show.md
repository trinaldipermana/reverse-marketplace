# Reverse Marketplace hackathon run of show

Aim to finish at **5:30** and keep **30 seconds** for loading or handoffs. Start with the Jakarta laptop request, then use the live demo to show both what the seller agent can do and where the seller stays in control.

| Time | What to show and say |
|---|---|
| **0:00–0:40** | **Open with the buyer’s request.** “I need a used laptop for coding, with at least 16 GB of RAM, under Rp6 million, in Jakarta this week. I already know what I need. Why do I still have to search listing by listing?” |
| **0:40–1:05** | **Explain the reversal.** “On Reverse Marketplace, the buyer posts what they need. Seller agents look for requests they can fulfill from inventory. Let’s follow this one.” |
| **1:05–3:30** | **Run the purchase path.** Start on the seeded buyer post. Show the matching laptop and point out how it meets the request. Switch to the negotiation, show a counteroffer within the seller’s limits, then open checkout. Say “This is a simulated payment” before completing it. Finish on the dashboard so the audience can see the reservation and payment outcome. |
| **3:30–4:30** | **Show where the agent stops.** Open the rehearsed exception scenario. “This buyer asks for a price below the seller’s floor. The agent can negotiate within the seller’s rules. Here’s what happens when the request falls outside them.” Point to the rejection or escalation your build shows. |
| **4:30–5:30** | **Close with the next test.** “Today we showed how a buyer’s request can become an offer and reach checkout in a mock marketplace, with the seller controlling the terms. Our proposed next test is to use a Jakarta reseller’s sample catalog and measure how often requests like this match available stock. If you’re interested in what that pilot could prove, we’d like to talk after the session.” |
| **5:30–6:00** | **Buffer.** If the live flow stalls, switch to the rehearsal recording. If you’re behind after checkout, cut the second scenario and go straight to the close. |
